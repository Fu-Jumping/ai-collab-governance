# 情景适配指南（ai-collab-governance）

> 用途：SKILL.md 第 1 节 L0-L3 分级的细化：逐机制取舍矩阵、升级触发信号、特殊团队变体。
> 原则：治理级别由「人数 × AI 代理数 × 共享程度」决定，不由项目重要程度决定。

## 1. 逐机制取舍矩阵

| 机制 | L1 个人 | L2 团队 | L3 强治理 | 砍掉它接受的风险 |
| --- | --- | --- | --- | --- |
| AGENTS.md AI 工作协议 | 必选（精简 6 条） | 必选（完整 18 条） | 必选 + 按代理角色定制 | 规则靠对话记忆，换会话即失效 |
| AI 不自行 commit/push | 必选 | 必选 | 必选（+ 提交签名/工具账号区分） | 不可控提交进入历史，回滚成本高 |
| 任务台账三要素 | 单文件必选 | 分板块必选 | 必选 + 看板化 | 责任真空、AI 凭猜测实现 |
| 出处回读纪律 | 必选 | 必选 | 必选 | AI"自由发挥"，实现与需求脱节 |
| raw 留痕 | 必选 | 必选 | 必选 | AI 使用过程不可回放、不可审计 |
| daily 汇总层 | 可砍 | 必选 | 必选 | 跨人跨天进度不可读 |
| TDD 红绿可验证 | 可选（逻辑改动建议） | 必选 | 必选 + CI 纯度检查脚本化 | "测试先行"沦为口号被字面绕过 |
| PR 模板 + 必跑矩阵 | 自查清单即可 | 必选 | 必选 + CI 全自动 | 合并前验证靠自觉 |
| 评审人本地复跑 | 自己复跑 | 必选（红端抽查） | 必选（全检） | 证据造假空间（引用作者结论） |
| `AI协作:` 尾注 | 建议 | 必选 | 必选 + 定期统计报告 | AI 参与不可见，无法评估依赖度 |
| 缺陷台账 | todo 加类型列即可 | 必选 | 必选 + 问题记录明细 | 缺陷处置无证据链 |
| 拦截记录台账 | 不需要 | 建议 | 必选 | 无法证明"规则在工作" |
| 长期约束台账（R 编号） | 建议 | 必选 | 必选 + 规则演进评审 | 同类事故重复发生 |
| 度量与定期报告 | 不需要 | 建议 | 必选 | 治理效果不可观测 |

## 2. 升级触发信号（出现任一条，升一级）

| 信号 | 说明 |
| --- | --- |
| 同类事故第二次发生 | 规则缺失或不可验证——升档并走事故升级流程 |
| 有 AI 产出的代码没人能解释 | 可解释性红线失守——立即回收合并权、补评审 |
| 台账出现"不知道谁在做"的任务 | 三要素失守——清理台账再继续 |
| 合并前验证开始"跳过一次没事吧" | 门禁靠自觉阶段——上 CI 或轮值评审 |
| 引入第二个长期协作的 AI 代理/工具 | 写权与留痕复杂度翻倍——补齐协议条款 |
| 外部贡献者出现（开源/跨组） | 信任模型变化——L3 |

**降级**同理：机制连续一个月零命中（如拦截记录为空、台账没人更新），先诊断是"没风险"还是"没人用"；确认是前者才降级，并在台账登记原因。

## 3. 特殊团队变体

### 课程小组（2~6 人 + 多 AI，有评分压力）
重点防三件事：**虚报完成度**（未收口不得写已完成 + 如实标注清单：可演示/只有替身/未实现三分类）、**老师需求变更**（变更台账 + 待定跟踪机制：未确认的下发变更不阻塞开发也不悄悄开工）、**答辩可解释性**（随机抽查讲代码——平时 `AI协作:` 尾注 + 五字段记录就是抽查复习提纲）。

### 开源社区式（外部贡献者 + 维护者）
信任模型变为"陌生贡献者"：PR 门禁权重加大（CI 全绿才可评审、DCO/签名）、AGENTS.md 作为贡献指南的一部分公开、外部贡献不进入 raw/daily 留痕体系（只走 PR 流程）、治理规则变更本身走 PR。

### 企业团队（跨职能 + 合规要求）
L3 之上追加：AI 产出审计追踪（谁在何时用哪个模型生成、谁批准合入——`AI协作:` 尾注 + PR 记录即最小实现）；敏感数据红线具体化（哪些仓禁止 AI 上传上下文）；度量进入例行质量报告；规则台账对接内审。

### 单人多代理（个人项目 + 2 个以上 AI 并行）
特殊风险是**代理互相踩踏**：同一工作区多代理时，每个代理只做台账里自己名下任务（raw 文件名按代理/角色分开）；改动留各自工作区，由人统一审阅提交；"暂存用显式路径禁 `git add -A`"在多代理场景从建议升为铁律。

## 4. 多工具并用的口径

ZCode / Claude Code / Codex 等并用时：**规则只写一份**（AGENTS.md，各工具均支持读取或桥接）；台账与留痕体系工具无关（都是 Markdown 文件）；`AI协作:` 尾注建议注明工具名（`AI协作: <工具> <说明>`），度量时可分工具统计依赖度。
