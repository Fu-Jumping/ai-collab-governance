# ai-collab-governance · AI 协作治理

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

给共享仓库里的 AI 编程代理立规矩：**人定标准、AI 提效、机器守门**。目标不是限制 AI，而是让高 AI 参与率不转化为失控——原项目 81.3% 的提交由 AI 深度参与，同时团队仍能讲清每一处代码。

适用：单人多代理 / 课程小组多 AI / 团队共享仓库，建立或加固治理。不适用：纯人工无 AI 的团队。

## 治理分级（先定级别，再上机制）

| 级别 | 情景 |
| --- | --- |
| L1 个人治理 | 单人 + 不限数量 AI 代理，自己是唯一合并人 |
| L2 团队治理（标准） | 2~6 人 + 多 AI 共享仓库 |
| L3 强治理 | 多板块多代理并行、外部贡献者、审计要求 |

治理不是一步到位：出现"同类事故第二次发生""有代码没人能解释""台账不知道谁在做"等升级信号时升一级（信号表见 skill 内）。

## 核心机制速览

1. **四层闭环**：规矩 → 事实 → 执行 → 反馈；顺序即设计（先事实源、再责任、再门禁、最后效率）；
2. **任务台账三要素**：唯一主责人 / 出处可回溯 / 证据；
3. **两级留痕**：人人只写自己的原始片段，日报唯一写权归次日汇总者（源自真实撞车事故的制度化解决）；
4. **TDD 红绿可验证**：`test:` 提交仅含测试且复跑必红，红绿数字证据进 PR 描述（口号式规则会被字面绕过——有真实打回案例）；
5. **五层拦截网**：自检 → CI 提交规范 → CI 构建 → 真实环境 → 独立复跑；只把零误报的检查放进强制门禁；
6. **红线**：可解释性（讲不清的产出不合入）、运动员/裁判分离、`AI协作:` 尾注可追溯、不泄密；
7. **事故 → 规则升级四步**：缺陷单 → 补丁 → 可验证条款 → R 编号台账（规则演进可审计）。

## 安装

**必须整目录复制**：

```bash
cp -r ai-collab-governance ~/.zcode/skills/
# 或项目内安装
mkdir -p <目标项目>/.agents/skills && cp -r ai-collab-governance <目标项目>/.agents/skills/
```
