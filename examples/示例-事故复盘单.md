## 1. 事故描述（现象，不含推断）

PR #31 提交序列为 `test: 订单明细列断言`（a1b2c3）→ `docs: 补充说明`（d4e5f6）。评审人检出 a1b2c3 复跑测试结果为 **42 passed / 0 failed（绿）**。查看 diff：a1b2c3 包含 `OrderDetailView.vue` 全部实现（+312 行）与 normalizer 改动；d4e5f6 仅含文档。

## 2. 根因分析

- 直接原因：实现代码被写进了 `test:` 提交，该提交上测试自然全绿。
- 为什么没被拦住：现行规则只有"test: 早于 feat:"，**没有任何检查项验证"test: 上测试必须失败"**——口号式规则可被字面满足。
- 深层根因：规则不可验证（缺失可执行条款），且当日提交由 AI 代理执行拆分，指令只约束了顺序没约束内容清单。

## 3. 规则升级（四步）

| 步 | 内容 |
| --- | --- |
| 旧规则为什么没拦住 | "同一功能 test: 早于 feat:"——顺序可查，内容与红绿不可查 |
| 新规则草案 | `test:` 提交仅含测试代码；其上复跑必须失败 |
| 可验证条款 | ① CI 检查 `test:` 提交 diff 不含非测试文件；② PR 模板新增"红端复跑数字"必填项；③ 评审人每周至少本地复跑抽查 1 个 `test:` 提交 |
| 台账登记 | R4：test: 提交纯度｜执行口径：CI diff 检查 + 红端复跑抽查（03-12，源自事件-0312-02） |

## 4. 修复与回归

- 修复提交：重写为 `test:(纯测试)` → `feat:(实现)` 三段序列；新旧末态 diff 校验零差异后 `--force-with-lease` 推送（e7g8h9）。
- 回归验证：`test:` 提交上复跑 **3 failed / 39 passed**（红，符合预期）；合并树复跑 **42 passed**（绿）。
- 同类点排查：`git log --pretty=%s | grep "test:"` 全量回看近两周 14 个 test: 提交，另发现 1 处夹带脚手架配置（无害但同类），一并规范。

## 5. AI 相关（如涉及）

- 是否 AI 产出引入：是——提交拆分由 AI 代理执行，指令未明确到文件级清单。
- AI 使用点五字段补录：任务 TODO-USER-058 → 类别：样板/提交整理 → AI 做了什么：按"先测试后实现"拆分提交 → 人工审核：复跑发现红端不红 → 结果：弃用原拆分，人给出文件级清单后重做。
- 对 AI 适用边界的启示：**涉及提交拆分、推送类操作的 AI 指令必须明确到文件级清单**；AI 满足"字面要求"的能力极强，规则必须写成可验证条款。
