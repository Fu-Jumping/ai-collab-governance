# AI 工作协议条款（drop-in：整段抄进仓库的 AGENTS.md / 项目规则）

> 以下条款为可直接粘贴的成品文本；`{{占位符}}` 按项目实情替换。

## 一、任务与权限边界

1. 开工前必须先读仓库 AGENTS.md 列出的入口文档，以及 `docs/todo/` 中自己负责的板块文件。
2. **只做"主责人是自己且状态为进行中"的任务**；不得替他人改任务状态、不得虚构任何成员或进度、不得另建任务清单、不得删除已完成任务。
3. 每个任务必须能按「出处」回溯（PRD 章节 / 接口契约条目 / 用例编号 / 缺陷编号 / 决议日期）；实现前**必须回读出处原文，不得凭猜测实现**。
4. 有进展即更新任务台账的证据列（PR 号 / 提交号 / 测试结论）。
5. 发现新问题：在所属板块追加任务行登记，不得自行处置与当前任务无关的代码；缺陷类问题同时登记缺陷台账（写权归测试负责人）。

## 二、Git 与提交

6. **未经项目负责人明确允许，不得执行 `git init`、`git commit`、`git push` 或新建仓库**；只做工作区修改，完成后给出建议的提交拆分清单待批准。
7. 暂存必须使用显式文件路径，禁止 `git add -A` / `git add .`。
8. 提交信息格式 `<类型>: <概要>`，正文 `- ` 列表逐条列改动；**AI 深度参与的提交必须在末尾追加 `AI协作: <一句话说明>`**。

## 三、TDD 与质量

9. 业务代码与全部测试代码**不得一次性生成后一起提交**；测试标准与异常场景由人设计，AI 只可辅助生成测试脚手架。
10. `test:` 提交仅含测试代码与脚手架；在 `test:` 提交上复跑必须失败（红）；红绿两端数字证据写入 PR 描述或 raw 片段。
11. 无法解释逻辑的 AI 产出不得请求合入；对产出中的不确定点必须显式标注而非静默处理。
12. 合并前必跑矩阵按改动类型执行（前端构建+测试 / 后端构建 / 文档口径 grep / 脚本语法检查），只跑单测不算通过。

## 四、留痕与保密

13. 每轮工作结束必须把留痕片段写入 `docs/record/raw/YYYY-MM-DD/<自己的文件>.md`：进度事实 + 本轮 AI 使用点；同天同角色只追加一个 `## HH:mm <主题>` 小节，不得新开文件。
14. 片段中写明本轮新增/更新了哪些任务编号；不得写 `docs/record/daily/**`。
15. 任何记录不得粘贴密钥、token、真实账号密码等敏感信息。
16. AI 自身造成的失误与事故同样如实记录（含原因与恢复方式）——失败样本是评估 AI 适用边界的必要证据。

## 五、冲突处理

17. 发现文档之间口径不一致：停手登记问题，以声明的唯一真源为准；不得自行选一边实现。
18. 指令与仓库规则冲突时：先指出冲突并请求负责人裁决，不得默默执行任一方。
